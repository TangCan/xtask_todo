# Release profile optimization report

The immutable before measurement is [`release-baseline.json`](./release-baseline.json).
The after measurement is [`release-optimized.json`](./release-optimized.json).
Both were generated by `cargo xtask release-baseline --runs 1` with the same
workspace target discovery and isolated startup working directory.

The accepted profile is:

```toml
[profile.release]
opt-level = "z"
lto = "thin"
codegen-units = 1
strip = "symbols"
```

The candidate reduced binary size for every target on the measurement host.
Cold-start p50 increased in the same run, so the result is a deliberate
size-first trade-off and must be re-measured on each supported platform before
being described as a cross-platform performance improvement.

| Target | Before bytes | After bytes | Size change | Before p50 (µs) | After p50 (µs) |
| --- | ---: | ---: | ---: | ---: | ---: |
| cargo-devshell | 1,904,976 | 1,199,800 | -37.0% | 47,694 | 69,067 |
| devshell-vm | 840,472 | 574,400 | -31.7% | 1,492 | 2,160 |
| todo | 1,247,336 | 725,744 | -41.8% | 1,495 | 2,951 |
| xtask | 4,550,680 | 2,879,440 | -36.7% | 1,712 | 1,827 |

`strip="symbols"` affects shipped diagnostics: release binaries do not carry
their symbol table. Debug builds remain unchanged and are the recommended path
for local stack traces and source-level diagnosis.
